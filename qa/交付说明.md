## 2. 架构与处理流程

1. P3 调用 `qa.service.answer(question, mode="auto")`。服务根据 `QA_BACKEND` 分派至真实后端或带假数据标识的三个演示用例。真实后端发生故障时返回状态或走规则降级。
2. 预检问题的指标、主体范围和时间条件。对“目前最厉害的新能源汽车公司是哪个？”提示先选择申请量、被引次数或 PageRank。“新能源汽车行业”用于限定研究范围。销量、营收、市值等问题返回数据范围提示。
3. 规则或 DeepSeek JSON Output 识别意图和槽位，后端校验白名单、类型和边界。实体链接使用 P1 标准名、原名、已确认别名和 RapidFuzz 候选。多实体或匹配歧义时由用户确认。
4. 通过 `core.database.run_query` 执行固定的参数化只读 Cypher，通过 `core.data_loader` 读取 P1 基础表和正式指标。辅助明细按当前专利范围过滤。Python 计算和校验业务指标，并从实际路径与引证明细封装证据子图。
5. 先用检索事实确定中文结论段。DeepSeek 只接收必要的证据段并返回排序，后端校验编号和固定首尾。模型缺配置、超时、请求失败、JSON 无效或输出未通过校验时，使用规则结论。结论阶段的降级复用已取回的事实。
6. 返回结果行、证据图、结论、已执行的 Cypher 和实际模式。仅含预计算或命中缓存的响应可返回空 Cypher。短期缓存只保留成功的真实结果，并按数据范围和连接环境区分。

### CQ10 指标与真实样例

按 `(citing_id, cited_id)` 去重。分母 `C_A` 是查询主体在当前时间窗内可映射到外部主体的引证边数。分子 `c(A,B)` 是其中映射给外部主体 B 的边数。暴露度为 `c(A,B) / C_A`。覆盖率用 `C_A` 除以当前范围内全部去重外部引用边数。多申请人被引专利可归到多个主体，各主体暴露度之和可能超过 100%。

分母为零时返回数据不足。分母小于 30 时仅展示暴露度。分母至少为 30 且暴露度达到 50% 时标记潜在单点依赖。主题分析按引用方技术主题统计。

国家电网样例中，已收录申请年为 2011–2024，含不完整的 2024 年。114 条外部引用中有 6 条可映射到外部主体，覆盖率 5.26%，涉及 5 个主体。深圳市优力特技术有限公司占 2 条，暴露度 33.3%。该样例仅展示暴露度，证据之一是 `CN103063953A → CN102156227A`。

在可映射外部引证主体子集内，专利引用仅是技术知识关联和依赖暴露的代理指标，不代表真实商业采购依赖或供应链依赖。

## 6. 本地配置与启动

在包含上述 P1 数据读取、P2 代码和 P3 页面版本的本地集成检出中安装 `requirements.txt`。先由 P1 准备样例契约数据及 `data/_sample/results/` 下的正式指标。若需要新建数据库，由 P1 在其版本上按 [运行说明](https://github.com/41423577arc-lab/patent-knowledge-graph/blob/5b4dfce/docs/run.md)，对计划用于样例的空白 Neo4j 实例执行 `python -m scripts.build_graph --sample`。

在仓库根目录的本地 `.env` 填写实际 Neo4j 连接和可选的 DeepSeek Key。系统环境变量优先。

```dotenv
DATA_DIR=data
USE_SAMPLE=true
QA_BACKEND=real
NEO4J_URI=bolt://127.0.0.1:7687
NEO4J_USER=
NEO4J_PASSWORD=
LLM_API_BASE=https://api.deepseek.com
LLM_MODEL=deepseek-flash
LLM_API_KEY=
```

```powershell
python -m pip install -r requirements.txt
python -m streamlit run app.py
```

访问 [本地 Streamlit 页面](http://localhost:8501)，进入「智能问答与关联路径」。DeepSeek 使用 OpenAI 兼容 SDK、非思考模式和 JSON Output。留空 Key 可运行真实规则问答。全量环境设置 `USE_SAMPLE=false`，将 `DATA_DIR` 指向含 `processed/`、`results/` 的全量数据根目录，并连接与这些数据一致的 Neo4j 实例。由 P1 负责空白全量实例的导入。

## 7. P3 前端对接

```python
from qa.service import answer

result = answer(question, mode="auto")
```

请求模式为 `auto`、`rule` 或 `llm`，响应的 `mode` 记录实际执行模式。保留现有字段 `ok`、`intent`、`slots`、`entities`、`data`、`graph`、`conclusion`、`cypher`、`mode`、`error`、`suggestions`。成功时 `error=null`，无证据图时 `graph.nodes` 与 `graph.edges` 均为空列表。

`ui/qa_workbench.py` 继续经 `answer()` 接入。`data` 是可 JSON 序列化的行列表，供数据表和 `ui/qa_visuals.py` 使用，例如 `patent_count`、`topic`、`year`、`weight` 和 `dependency_exposure`。关系图使用 `graph`，可解释面板展示路由、槽位、已解析实体及实际执行的查询。实体歧义时读取 `entities.candidates`，将用户选择的实体写入重新提交的问题。澄清建议来自 `suggestions`。
