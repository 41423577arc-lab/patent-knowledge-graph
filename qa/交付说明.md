## 2. 架构与处理流程

1. P3 调用 `qa.service.answer(question, mode="auto")`。服务根据 `QA_BACKEND` 分派至真实后端或带假数据标识的三个演示用例。真实后端发生故障时返回状态或走规则降级。
2. 预检问题的指标、主体范围和时间条件。对“目前最厉害的新能源汽车公司是哪个？”提示先选择申请量、被引次数或 PageRank。“新能源汽车行业”用于限定研究范围。销量、营收、市值等问题返回数据范围提示。
3. 规则或 DeepSeek JSON Output 识别意图和槽位，后端校验白名单、类型和边界。实体链接使用 P1 标准名、原名、已确认别名和 RapidFuzz 候选。多实体或匹配歧义时由用户确认。
4. 通过 `core.database.run_query` 执行固定的参数化只读 Cypher，通过 `core.data_loader` 读取 P1 基础表和正式指标。辅助明细按当前专利范围过滤。Python 计算和校验业务指标，并从实际路径与引证明细封装证据子图。
5. 先用检索事实确定中文结论段。DeepSeek 只接收必要的证据段并返回排序，后端校验编号和固定首尾。模型缺配置、超时、请求失败、JSON 无效或输出未通过校验时，使用规则结论。结论阶段的降级复用已取回的事实。
6. 返回结果行、证据图、结论、已执行的 Cypher 和实际模式。仅含预计算或命中缓存的响应可返回空 Cypher。短期缓存只保留成功的真实结果，并按数据范围和连接环境区分。

### CQ10 指标与真实样例

按 `(citing_id, cited_id)` 去重。分母 `C_A` 是查询主体在当前时间窗内可映射到外部主体的引证边数。分子 `c(A,B)` 是其中映射给外部主体 B 的边数。暴露度为 `c(A,B) / C_A`。覆盖率用 `C_A` 除以当前范围内全部去重外部引用边数。多申请人被引专利可归到多个主体，各主体暴露度之和可能超过 100%。

分母为零时返回数据不足。分母小于 30 时仅展示暴露度。分母至少为 30 且暴露度达到 50% 时标记潜在单点依赖。主题分析按引用方技术主题统计。

国家电网样例中，已收录申请年为 2011–2024，含不完整的 2024 年。114 条外部引用中有 6 条可映射到外部主体，覆盖率 5.26%，涉及 5 个主体。深圳市优力特技术有限公司占 2 条，暴露度 33.3%。该样例仅展示暴露度，证据之一是 `CN103063953A → CN102156227A`。

在可映射外部引证主体子集内，专利引用仅是技术知识关联和依赖暴露的代理指标，不代表真实商业采购依赖或供应链依赖。

## 7. P3 前端对接

```python
from qa.service import answer

result = answer(question, mode="auto")
```

请求模式为 `auto`、`rule` 或 `llm`，响应的 `mode` 记录实际执行模式。保留现有字段 `ok`、`intent`、`slots`、`entities`、`data`、`graph`、`conclusion`、`cypher`、`mode`、`error`、`suggestions`。成功时 `error=null`，无证据图时 `graph.nodes` 与 `graph.edges` 均为空列表。

`ui/qa_workbench.py` 继续经 `answer()` 接入。`data` 是可 JSON 序列化的行列表，供数据表和 `ui/qa_visuals.py` 使用，例如 `patent_count`、`topic`、`year`、`weight` 和 `dependency_exposure`。关系图使用 `graph`，可解释面板展示路由、槽位、已解析实体及实际执行的查询。实体歧义时读取 `entities.candidates`，将用户选择的实体写入重新提交的问题。澄清建议来自 `suggestions`。

## 10. 第三阶段 · DeepSeek 联网补充（本地待审核）

本轮独立工作树基于 `origin/p2-qa` 的 `aa176ad`，核对的 P3 与 P1 远程版本分别为 `6ef1cfc` 和 `0549afd`。图谱问答仍使用既有 12 个意图及 481 件样例。开关启用后，路由会识别明确且在新能源汽车范围内的公开资讯问题，单独查询 DeepSeek。图谱内部指标、实体歧义、数据缺失和连接失败沿用本地处理。未说明统计期的商业排行先询问地区和时间。

### 配置与接口

沿用第 6 节的 DeepSeek 配置，真实后端默认开启联网。已有 `QA_WEB_SEARCH_ENABLED=false` 配置会继续关闭联网。修改本地配置后需重启 Streamlit。可配置 `QA_WEB_SEARCH_TIMEOUT=45`，接受 1–60 秒，单次请求无自动重试。规则模式和演示桩均不联网。未配置 Key 时仍可查本地图谱。第一期每次实时检索，联网结果不进入图谱缓存。

[`web_search.py`](web_search.py) 通过现有 OpenAI 依赖中的 HTTP 客户端发起非流式 Chat Completions。非思考模式只声明 `deepseek_web_search`。只保留有已完成工具调用、来源 URL 与官方引用注解对应、引用位置在正文内的片段。来源日期由工具提供，缺失时显示“日期未提供”。客户端不访问响应中的第三方链接，也不会向 Neo4j 写入网页内容。[DeepSeek 联网工具文档](https://api-docs.deepseek.com/zh-cn/guides/web_tools/)

P3 和 P5 的现有检查要求固定顶层字段。联网成功使用 `ok=true`、`intent=""`、`mode="llm"`、空 `data`、空图和空 `cypher`。可点击链接和“公开互联网”标识放在 `conclusion`。联网故障通过 `error` 返回。P3 当前的响应归一化接受该结构，但其状态助手把空业务行、空图的成功结果归到 `DATA_UNAVAILABLE`。P3 可为空意图的成功联网结论增加展示分支，显示「联网搜索回答」，折叠空的统计与图谱面板，新增等待提示及可选开关。若需要结构化 `source_type`、`sources`，先由 P2、P3、P5 一起更新契约和测试。

P3 兼容交接方案是在真实后端的通用空证据判断之前，检查 `ok=true`、`mode="llm"`、`intent=""`、`data=[]`、图节点与边均为空、`cypher=""` 且 `conclusion` 非空。命中时显示联网成功和来源徽标，保留结论中的 Markdown 链接，跳过图表和 Cypher 展示。已有图谱和演示成功响应携带正式意图，可继续进入各自的面板。等待阶段可提示「查询中，可能检索公开网页」，因为完成响应前前端尚不知道实际路由。P3 需用联网成功、空证据错误、普通图谱响应三类隔离测试确认该约定。

最新销量问题要求带引用的销量陈述包含近期统计年月。近期证据不足时返回可操作的错误提示。政策问答要求注明发文和适用时间，报告只对实际抽查的事实和时效作出结论。Web 客户端固定访问 DeepSeek 官方 API，返回 URL 只用于展示，不由服务端抓取。引用 URL 通过协议、主机与公开地址校验，不接受本机、内网或实例元数据地址。

### 默认联网配置复验

在 481 件真实样例上，未设置联网开关，以 `auto` 逐一提交 12 个正式意图。12 项均成功返回本地证据，实际模式均为 `llm`，网页请求 0 次，响应耗时 1.218–2.312 秒。显式 `llm` 的国家电网「主体 → 专利 → 主题 → 领域」问题也返回本地图谱证据，网页请求 0 次。关闭联网后，`auto` 正常回答本地排名，并对政策问题返回原有范围提示。

两个主体同时出现时返回 2 个候选，评价指标缺失时提示明确口径。移除 Key 后，本地排名以规则模式返回，公开政策问题提示缺少 Key，无外部 HTTP 请求。最终真实联网复跑覆盖最新销量（`llm`）与政策（`auto`）。首轮分别为 5 次和 6 次搜索、4 个和 6 个引用来源，耗时 2.828 秒和 4.172 秒，API 返回 6,368 和 10,459 Tokens。图谱模式的耗时包含意图与答案组织的模型请求。
