# 专利知识图谱项目 · 现状说明（给组员看）

> 一句话：我们把原来那个「专利授权预测」的神经网络实验，改造成了老师要求的**知识图谱 + 应用系统**。
> 现在它是一套**能现场演示**的「新能源汽车专利技术图谱」，不是设想，是已经跑起来的系统。

---

## 1. 为什么要改

| 作业要求 | 原来的项目 | 现在 |
|---|---|---|
| 知识图谱系统 | 一个 GNN 二分类实验 | ✅ 4 类实体 + 4 类关系的图谱 |
| 图数据库存储 | 只有 pickle / .pt 文件 | ✅ Neo4j 5.26，97,432 个节点、228,866 条关系 |
| 应用系统 | 输出一个 0/1 标签 | ✅ 6 个功能页面的可视化系统 |
| 现场演示 | 跑不起来（缺 `main.py`、`graphgps` 包，路径是 Mac 的） | ✅ 一条命令启动，查询 0.1–0.3 秒 |
| 5 个能力问题、含多跳 | 没有 | ✅ 6 个问题，其中 3 个是多跳 |

**结论：原来的代码不再作为主体**，只保留它作为「如果要做授权风险预测」的备选亮点。
新系统全部在 `kg_system/` 目录里。

## 4. Schema（四类实体、四类关系）

| 实体 | 属性 | 为什么这样设计 |
|---|---|---|
| **Patent 专利** | 公开号、标题、年份、主分类、法律状态、是否授权、被引次数 | 图谱的核心节点 |
| **Company 企业** | 名称（标准化后的申请人） | 用来做企业画像与竞争分析 |
| **Inventor 发明人** | 姓名 | 支持「谁在研发」类问题 |
| **TechClass 技术小类** | IPC 前 4 位、所属板块 | 把专利挂到「三电」叙事上 |

| 关系 | 方向 | 语义 |
|---|---|---|
| `APPLIED` | 企业 → 专利 | 申请 |
| `INVENTED` | 发明人 → 专利 | 发明 |
| `CITES` | 专利 → 专利 | 引用（引用方指向被引用方） |
| `IN_CLASS` | 专利 → 技术小类 | 属于 |

**答辩高频问题「为什么年份是属性不是实体」**：年份只用于筛选和聚合，不参与连接；把它做成实体只会让图变碎、查询变慢。同理，国家、法律状态也是属性。这条要背下来。

## 5. 六个页面 = 六个能力问题

| 页面 | 回答什么问题 | 跳数 |
|---|---|---|
| 图谱概览 | 这个图谱里有什么、规模多大 | 0 |
| 企业技术画像 | 某企业有多少专利？授权率？技术集中在哪？ | 1–2 跳 |
| 引用关系多跳分析 | 谁在引用某企业的专利？技术扩散到哪？ | **2 跳** |
| 核心专利识别 | 哪些专利最被认可？哪家企业影响力最大？ | 2 跳 |
| 技术演进趋势 | 各技术板块 2015–2025 怎么变 | 1 跳 |
| 专利检索 | 按关键词查专利、看归属 | 1 跳 |

其中 **多跳问题有 3 个**，满足「至少 2 个多跳」的要求。

## 6. 现在能演示的真实结果

- **北京新能源汽车股份有限公司**：474 件专利，授权率 65.6%，技术集中在「电控/驱动」264 件
- **谁在引用它**（2 跳）：长安汽车 8 件、长城华冠 6 件、比亚迪 5 件、北汽福田 4 件 → 这就是「技术跟随与竞争」的证据
- **核心专利第一名**：CN103944201A《一种电动汽车定时充电桩》，被引 **36** 次
- **趋势**：2015–2025 年各技术板块的专利数量变化，可直接看出「充换电」板块的上升

这些数字都是从数据库里现查的，不是写死的，老师现场换企业也能查。

## 8. 怎么开机演示（三步）

```powershell
# 1) 启动数据库（黑窗口别关）
powershell -File kg_system\scripts\start_neo4j.ps1

# 2) 再开一个窗口，启动网页
powershell -File kg_system\scripts\start_app.ps1

# 3) 浏览器打开 http://127.0.0.1:8501
```

## 11. 老师最可能问的 6 个问题（提前背）

1. **为什么专利是实体、年份不是？** → 年份只做筛选聚合，不参与连接；做成实体只会让图更碎。属性与实体的取舍标准是「是否需要作为连接点」。
2. **数据准确率多少？** → 抽 50 条人工核对，关系抽取准确率约 XX%（D2 补数字），错误主要来自企业名简称。
3. **关系方向怎么定？** → 统一「引用方 → 被引用方」，与专利审查文献方向一致；申请是「企业 → 专利」。
4. **重复实体怎么处理？** → 用标准化申请人 + 去方括号/国家码 + 人工抽查；已知未合并子公司（如比亚迪系）。
5. **数据量扩大一百倍还行吗？** → 现在 2.5 万专利、10 万关系是单机 Neo4j 的轻松量级；扩到 250 万需要按年份分区、改用 `neo4j-admin` 批量导入、给 `CITES` 加索引。
6. **这张图谱谁会用？** → 行业分析师做技术路线对比、投资研究判断企业技术积累、政策部门看技术分布；对应「企业画像 + 多跳引用 + 核心专利」三个页面。

## 12. 给不做技术的同学：四个词就够

- **知识图谱**：把「谁—做了什么—和谁有关」画成一张网，让机器能顺藤摸瓜。
- **Schema**：先规定这张网里允许有哪些「东西」和「关系」，相当于数据库的表结构。
- **Neo4j**：专门存这种网的数据库，查询语言叫 Cypher。
- **多跳**：从 A 走到 B 再走到 C，比如「企业 → 专利 → 引用了它的专利 → 那件专利的申请企业」。
